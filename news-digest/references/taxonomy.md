# 打分标准（triage 必读）

写 `triage.json` 时用。你手上有每条的标题、来源、tier（1 最权威）和一段短摘要。
**同批次口径必须一致**：先通读全部条目，再统一给分，不要逐条孤立判断。拿不准的，importance 压到 0.5 以下并标 `needs_review`。

## 相关性

以 `triage_input.json` 的 `criterion` 为准：每日运行是 profile 的 `interests`，临时运行是用户这次的关注点。与之无关的、软文、营销、没有实质信息的 → `drop`。订阅源会带来很多无关条目，放心丢。

## category（单选）

只能取 `triage_input.json` 里 `categories` 的 `name`（来自 `categories.json`）。

- **先看主体，而不是影响**：一条讲"某地出台 AI 监管条例"的稿子，主体是监管 → `政策监管`（tags 里可以带 AI），不要归 `AI`。
- 跨领域的取最核心的主题，不要双分类。确实归不进去才用 `其他`。

## importance（0–1，主排序键）

| 区间 | 含义 | 判据 |
|---|---|---|
| 0.85–1.0 | 重大 | 改变行业格局 / 巨头级发布 / 重大政策落地 / 黑天鹅 / 巨额并购 |
| 0.65–0.84 | 重要 | 值得单独推送，领域从业者必须知道 |
| 0.45–0.64 | 一般 | 领域内有用，知道更好 |
| 0.25–0.44 | 边缘 | 仅作补充 |
| < 0.25 | 丢弃 | 日常动态、纯观点、软文、无实质信息 |

- 低于 `min_importance`（默认 0.35）的事件不落盘；直接放进 `drop` 也可以。
- **同批次最多 1–2 条 ≥ 0.85**；打出五条 0.9，说明尺度松了，整体下调一档。
- importance 是**事件**的分数：多家报道同一件事，给这个事件一个分，不因报道多而叠加。

## 同一事件

- 报道同一件事的条目进同一个 event；`primary` 选信息最完整、tier 最小的那条。
- 观点 / 评论类不当 primary，除非这个事件只有它一篇。
- 同一天、同一主体、同一动作 → 同一个 event；有新的实质信息（例如"发布"之后的"开放下载"）→ 新的 event。

## 其余字段

- `novelty`（0–1）：已有事件的第 N 次跟进给 0.2–0.4；首次披露给 0.7 以上。
- `sentiment`：`positive` / `neutral` / `negative`，只评价事件本身，不做投资建议。

## flags

- `is_breaking`：正在发生且持续更新（发布会直播、突发事故）。
- `is_opinion`：评论 / 专栏 / 社论。**观点类 importance 上限 0.6。**
- `needs_review`：信息源单一、数据矛盾，或你没把握。
