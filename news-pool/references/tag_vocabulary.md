# 标签词表使用规则

词表本体在 **`references/tags.txt`**（一行一个，支持 `#` 注释）。归一化的目的：同一类新闻在不同批次、不同模型运行下拿到一致的 tag，这样前端按 tag 聚合、做订阅筛选才靠谱。

## 打标签的四条规则

1. **优先从词表选**。每条**最多 10 个**，按相关性降序；信息量小的稿子给 2–4 个就够，别凑数。
2. **粒度互补**：给一个宽的、一个窄的（`大模型` + `MoE`），别给三个同义的（`大模型` + `LLM` + `AI模型`）。
3. **实体不打 tag**。公司 / 人物 / 产品名一律进 `entities.companies` / `people` / `products`，
   例如 OpenAI 进 entities，**不要**打成 tag——实体是开放集合，塞进 tag 会永远归一化不了。
4. **别重复 category 已表达的意思**：category 已经是 `AI` 就不要再打 `AI`；`region` 已经标了地区也不要打地区 tag。

## 词表没有的词怎么办

允许自造，但必须：**简短名词**、**不中英混写**、**不用 hashtag**（技术缩写如 RAG / MoE / API 这类固定写法可以保留英文）。

`check` 和 `finalize` 会统计词表外的 tag 并提示，形如：

```
[nd] warning: tags outside tags.txt (add the recurring ones there): 量子计算(3), 端侧推理(2)
```

看到高频的新词就往 `tags.txt` 里加，词表会随着使用自己长起来。这是**提示不是报错**，不会中断落盘。

## 维护约定

- 加词前先想清楚：这个词是**会反复出现的主题**，还是**一次性实体**？后者不该进词表。
- 近义词只保留一个（有 `端侧AI` 就别再加 `边缘计算`，除非你确实需要区分）。
- 删除词要谨慎：历史 JSON 里可能已经用了，删了不会报错但会让聚合结果断层。
- profile 里放一份自己的 `tags.txt` 即整体替换内置词表。
